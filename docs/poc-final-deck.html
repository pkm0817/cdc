"Debezium 이 불안정한가"를 먼저 물으면 대안이 둘인 것처럼 보입니다. 실제로는 하나입니다. 원본에 소프트 삭제를 넣을 수 있는지는 원천 시스템의 스키마·업무 로직 변경이라 CDC 팀 단독으로 정할 수 없습니다. 장애가 난 뒤에 시작하면 늦습니다.

06. 결정이 필요한 것

엔진 결함은 무엇을 보고 판단합니까

문제 — 지금은 "재현 시 판단" 이라고만 돼 있습니다

기준이 없으면 장애 한 번이 곧 전환 논의가 됩니다. 판정식을 미리 고정하자는 제안입니다.
유형판정식 (제안)무엇으로 재는가지금 가능한가
행업 엔진 스레드는 살아 있는데 이벤트 0건이고 슬롯이 10분 이상 정지 기존 지표 조합으로 계산 가능 경보 규칙 추가 필요

그리고 "결함"이라 부르려면

(1) 같은 시나리오 3회 이상 재현 — 1회는 환경 잡음일 수 있습니다. (2) 최신 패치 버전에서도 재현 — 고쳐진 것을 근거로 전환할 수 없습니다. (3) 업스트림 이슈 확인 — 알려진 것이면 수정 일정이 판단 재료가 됩니다.

셋 중 둘은 지금도 판정됩니다

오프셋 오염은 V3 에서 실제로 탐지됐고, 메모리 누수는 지표가 이미 나옵니다. 행업만 경보 규칙이 없습니다 — 기존 규칙은 30분 창이고 heartbeat 미설정을 잡는 용도라 목적이 다릅니다.
