    실제로 남은 조치는 이것 하나다

    max_slot_wal_keep_size = -1 은 상한이 없다는 뜻입니다. 컨슈머가 오래 죽으면 WAL 이 디스크를 채울 때까지 쌓이고, 그러면 source DB 가 먼저 죽습니다. 슬롯 무효화는 재동기화로 복구되지만(V3 에서 101/101 로 확인) 디스크 고갈은 원천 장애입니다.

    둘 다 나쁜 선택지 중에서는 슬롯 무효화가 낫습니다. CdcSlotLagCritical 경보 설명문도 같은 말을 하고 있습니다 — "max_slot_wal_keep_size 가 -1 이면 디스크가 찰 때까지 계속 자란다. source DB 가 먼저 죽는다." 경보는 이미 그 상황을 예고하고 있는데 정작 상한이 없습니다.

        command:
      - postgres
      - -c
      - wal_level=logical
      # ... 기존 항목 ...
      - -c

    배경
